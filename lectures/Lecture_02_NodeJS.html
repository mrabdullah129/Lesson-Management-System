Part 1 - 0 se 30 Minute

Introduction to Node.js 🟢

Node.js JavaScript ko browser ke bahar run karne ki power deta hai. Is ki wajah se JavaScript sirf front-end tak limited nahi rehti, balki server-side development mein bhi use hoti hai.

Node.js aik open-source, cross-platform runtime environment hai jo JavaScript ko browser ke bahar run karta hai aur Google Chrome ke V8 JavaScript Engine par built hai.
🌍
Open-source
Node.js freely available hai. Developers is ko use, improve aur share kar sakte hain.
💻
Cross-platform
Ye Windows, Linux aur macOS par run kar sakta hai.
⚙️
Runtime Environment
Runtime ka matlab: aisa environment jahan code execute hota hai. Node.js JavaScript code ko browser ke bahar execute karta hai.
Key Points 
// What is Node.js?
1. Node.js open-source aur cross-platform runtime environment hai.
2. Ye JavaScript ko browser ke bahar run karta hai.
3. Ye Google Chrome ke V8 JavaScript Engine par built hai.
Core Features

Node.js Kyun Use Karein? ⚡

Node.js fast, scalable aur event-driven approach deta hai. Is liye real-time apps, APIs aur high-traffic servers ke liye useful hai.

🚦
1. Asynchronous & Non-blocking
Node.js multiple requests ko handle kar sakta hai bina is baat ka wait kiye ke pehla kaam complete ho. Is se performance aur scalability improve hoti hai.
🍽️
Real-life Example: Restaurant Waiter
Traditional blocking: waiter aik order leta hai, food serve hone ka wait karta hai, phir next order leta hai.

Node.js non-blocking: waiter multiple orders leta hai aur jiska food ready hota hai us ko serve kar deta hai.
🧵
2. Single-threaded but Highly Scalable
Node.js single thread use karta hai, lekin event-driven architecture ki wajah se thousands of requests manage kar sakta hai.
🚀
3. Fast Performance
Node.js V8 engine use karta hai jo JavaScript ko directly machine code mein convert karta hai. Isi wajah se execution fast hoti hai.
🖥️
4. Cross-platform
Node.js Windows, Linux aur macOS par run hota hai. Is ka matlab same technology different systems par use ho sakti hai.
💬
Chat Apps ke liye Suitable
Chat applications mein bohat se users ek sath messages bhejte hain. Node.js non-blocking aur event-driven model ki wajah se aisi apps ke liye useful hota hai.
👥

Part 2 - 30 se 60 Minute

Node.js Architecture 🗺️

Node.js ka architecture event-driven, non-blocking I/O aur client-server model par based hai. Is architecture se server multiple requests efficiently handle karta hai.

📡
Event-driven
Kaam events ki base par hota hai. Jab koi event occur hota hai, Node.js us ko process karta hai.
⚡
Non-blocking I/O
Input/output operations ke liye wait nahi karna parta. Node.js next request handle karta rehta hai.
🌐
Client-Server
Client request send karta hai, server us request ko process karke response wapas bhejta hai.

Architecture Flow

1. Client Request
→
2. Event Queue
→
3. Event Loop
→
4. Background Threads
→
5. Response to Client
1
Client request send karta hai
User browser, mobile app ya API client se request send kar sakta hai.
2
Request Event Queue mein jati hai
Queue request ko temporarily store karti hai taa ke Event Loop usay process kar sake.
3
Event Loop request process karta hai
Event Loop decide karta hai ke kaunsi request next handle hogi.
4
Heavy tasks background threads handle karte hain
File system ya heavy operations ko background mein process kiya ja sakta hai.
5
Response client ko wapas bhej diya jata hai
Task complete hone ke baad server result client ko send kar deta hai.
Modules

Node.js Modules 📦

Modules reusable blocks of code hote hain. Node.js mein har file ko aik module treat kiya jata hai. Modules se code organize aur reuse karna easy ho jata hai.

Real-life example: Modules book ke chapters ki tarah hote hain. Har chapter aik specific topic handle karta hai, isi tarah har module aik specific kaam handle karta hai.
🧱
1. Core Modules
Ye built-in modules hote hain jo Node.js ke sath already available hote hain. In ko install karne ki zaroorat nahi hoti.
  • fs - File System
  • http - Web server create karna
  • path - File paths handle karna
  • os - Operating system info
📝
2. Local Modules
Ye developer khud create karta hai. In ka use code ko organize karne ke liye hota hai.
  • Project ke different parts separate files mein rakhna
  • Reusable functions banana
  • Code ko clean aur maintainable banana
📥
3. Third-party Modules
Ye external packages hote hain jo NPM se install kiye jate hain.
  • express
  • mongoose

Event Loop - Node.js ka Heart 🔁

Event Loop Node.js ka central concept hai. Ye asynchronous operations ko handle karta hai aur continuously check karta rehta hai ke next kaam kya process karna hai.

❤️
Heart of Node.js
Event Loop ko Node.js ka heart kaha jata hai kyun ke ye async tasks ko manage karta hai.
🔄
Continuously Check
Event Loop call stack, event queue aur callback queue ko continuously check karta hai.
Call Stack
↔
Event Queue
↔
Callback Queue
↔
Event Loop
Simple Explanation: Event Loop traffic police officer ki tarah hota hai jo decide karta hai ke kaunsi request next jayegi.
Callbacks

Callbacks 📞

Callback aik function hota hai jo kisi doosre function ko argument ke tor par pass kiya jata hai. Ye tab execute hota hai jab task complete ho jata hai.

🧩
Definition
Callback = aisa function jo argument ke tor par pass hota hai aur task complete hone ke baad chalaya jata hai.
🍔
Food Order Example
Aap food order karte hain aur waiter ko call karte hain. Jab food ready hota hai, waiter aap ko call back karta hai. Isi tarah callback task complete hone ke baad run hota hai.
Concept 
// Callback ka idea
Task start hota hai
Node.js wait nahi karta
Task complete hota hai
Callback function run hota hai
Event Emitters

Event Emitters 📡

Event Emitters events ko emit aur listen karne ke liye use hote hain. Ye Observer pattern par based hote hain.

📢
Emit Events
Jab koi kaam complete hota hai ya koi action hota hai, event emit kiya ja sakta hai.
👂
Listen Events
Listener event ka wait karta hai. Event trigger hota hai to related callback/function run hota hai.

Example Use Cases

📁
File Upload Completion
File upload complete ho to event trigger ho sakta hai.
🖱️
Button Click
Button click aik event hai jo listener ke through handle hota hai.
🌐
Network Request
Network request complete hone par event ya callback response handle kar sakta hai.
🔗
Relation Between Event Loop, Event Emitters and Callbacks
  • Event Loop callbacks ko manage karta hai.
  • Event Emitters events trigger karte hain.
  • Callbacks response handle karte hain.
