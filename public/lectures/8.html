🕐 0 - 30 Minutes: Authentication aur JWT ka Introduction

🔑 Authentication kya hai?

Authentication woh process hai jisme verify kiya jata hai ke user kaun hai.

👉 Example: Username aur password use karke Facebook mein login karna.

🔐 Authorization kya hai?

Authorization decide karta hai ke user kis cheez tak access kar sakta hai.

👉 Example

Admin posts delete kar sakta hai.

👉 Example

User sirf posts view kar sakta hai.

🤔 Traditional Session-Based Authentication

  • Server session data store karta hai.
  • Cookies use hoti hain.
👉 Problem: Large distributed systems ke liye scalable nahi hota.

🌐 JWT (JSON Web Token) kya hai?

JWT client aur server ke darmiyan information transmit karne ka compact aur secure tareeqa hai.

👉 Yeh hota hai:

Self-contained Digitally signed Stateless

📦 Real-Life Analogy

JWT ko movie ticket 🎟️ ki tarah sochain:

  • Aap ticket dikhate hain → cinema mein enter karte hain.
  • Dobara poochne ki zaroorat nahi hoti.

🎯 REST APIs mein JWT kyun?

REST APIs stateless hoti hain, is liye JWT madad karta hai:

  • Server par session store karne se bachata hai.
  • Easily scale hota hai.
  • Multiple services ke across kaam karta hai.

🎓 Student Activity (5 mins)

“Large apps mein server par sessions store karna problem kyun ban sakta hai?”

🕑 30 - 60 Minutes: JWT ki Structure

JWT ke 3 parts hotay hain:

Header.Payload.Signature

🧩 1. Header

Is mein yeh cheezen hoti hain:

  • Token type (JWT)
  • Algorithm used

👉 Example:

{ "alg": "HS256", "typ": "JWT" }

📄 2. Payload

Is mein claims (data) hota hai:

  • User ID
  • Role
  • Expiry time

👉 Example:

{ "userId": 101, "role": "admin", "exp": 1712345678 }

🔏 3. Signature

Yeh ensure karta hai ke token tamper nahi hua.

👉 Yeh cheezen use karke create hota hai:

  • Header
  • Payload
  • Secret key

🔍 Visual Understanding

JWT = Base64(Header) + "." + Base64(Payload) + "." + Signature

🎯 Real-Life Example

Header

Ticket type

Payload

Aap ka seat number

Signature

Official stamp

🕒 60 - 90 Minutes: REST APIs mein JWT kaise kaam karta hai

🔄 JWT Authentication Flow

  1. User login karta hai.
  2. Server credentials verify karta hai.
  3. Server JWT generate karta hai.
  4. Client token store karta hai.
  5. Client requests mein token send karta hai.
  6. Server token validate karta hai.

📡 Request Example

Authorization: Bearer <token>

🧠 Step-by-Step Explanation

Step 1: Login

User send karta hai:

{ "username": "Ali", "password": "1234" }

Step 2: Token Generation

Server return karta hai:

{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

Step 3: Client Stores Token

LocalStorage / SessionStorage

Step 4: Access Protected Routes

Client send karta hai:

Authorization: Bearer eyJhbGc...

Step 5: Server Verifies Token

  • Signature check karta hai.
  • Expiry check karta hai.

🕓 90 - 120 Minutes: Advantages, Limitations aur Best Practices

✅ JWT ke Advantages

  • Stateless (server storage nahi hoti)
  • Scalable
  • Fast authentication
  • Domains ke across kaam karta hai.

❌ JWT ki Limitations

  • Token ko easily revoke nahi kiya ja sakta.
  • Token size large ho sakta hai.
  • Agar properly store na ho to security risks hotay hain.

⚠️ Security Best Practices

🔒 1. HTTPS use karein

Token theft prevent karein.

⏳ 2. Expiration Time use karein

Tokens expire hone chahiye.

🔑 3. Strong Secret Key use karein

Hacking prevent karein.

📦 4. Payload mein Sensitive Data store karne se bachein

Payload readable hota hai.

🔄 5. Refresh Tokens use karein

Long sessions ke liye.
