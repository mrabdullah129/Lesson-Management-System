0–30 Minutes

1️⃣ REST API Security ka Introduction

🔹 REST kya hai?

REST (Representational State Transfer) web services design karne ke liye aik architectural style hai. REST APIs HTTP methods use karti hain:

  • GET
  • POST
  • PUT
  • DELETE

Real-Life Example:

Restaurant ka sochain:

  • Menu = API endpoints
  • Order = Request
  • Food served = Response
  • Waiter = Server

🔐 Security kyun important hai?

Agar APIs secure na hon:

  • Hackers user data chura sakte hain
  • Attackers servers ko overload kar sakte hain
  • Unauthorized users restricted data access kar sakte hain

Example:

Sochain aik banking API authentication ke baghair ho — koi bhi banda paisay check ya transfer kar sakta hai!

🌍

2️⃣ CORS (Cross-Origin Resource Sharing)

Definition:

CORS aik security mechanism hai jo control karta hai ke web server par resources ko kisi doosray domain se kaise request kiya ja sakta hai.

Browsers CORS enforce karte hain.

Real-Life Example:

Aap Hostel A mein rehte hain. Sirf Hostel A ke students enter kar sakte hain.

Agar Hostel B se koi enter karna chahta hai, to permission required hai.

🧠 Same-Origin Policy

By default, browsers block kar dete hain:

Frontend: http://example.com API: http://api.example.com

Agar related bhi hon, phir bhi ye different origins hain.

⚙️ CORS kaise kaam karta hai

Server aise headers send karta hai:

Access-Control-Allow-Origin: https://example.com Access-Control-Allow-Methods: GET, POST Access-Control-Allow-Headers: Content-Type

🚨 CORS Security Best Practices

  • ❌ Sensitive APIs ke liye kabhi bhi Access-Control-Allow-Origin: * use na karein
  • ✅ Sirf trusted domains allow karein
  • ✅ Methods restrict karein
  • ✅ Tokens server-side validate karein

🎯 Student Activity (5 Minutes)

Students se poochain:

  1. CORS kyun exist karta hai?
  2. Agar banking APIs ke liye * allow kar dein to kya hoga?
  3. Kya CORS server-side security feature hai ya browser-side?

3️⃣ XSS (Cross-Site Scripting)

Definition:

XSS aik attack hai jahan malicious scripts trusted websites mein inject ki jaati hain.

🔥 XSS ki Types

  1. Stored XSS
  2. Reflected XSS
  3. DOM-based XSS

🧠 Real-Life Example:

Aik comment box users ko comments post karne deta hai.

Attacker enter karta hai:

<script>alert("Hacked!")</script>

Agar sanitize na kiya jaye, to page visit karne wala har user ye dekhta hai.

🎯 XSS ka Impact

  • Cookie theft
  • Session hijacking
  • Malicious sites par redirect

🛡️ Prevention Techniques

  • Input validation
  • Output encoding
  • HTTPOnly cookies use karein
  • Content Security Policy (CSP) use karein
🌊

4️⃣ DDoS (Distributed Denial of Service)

Definition:

DDoS aik attack hai jahan multiple systems server ko traffic se flood karte hain taake server unavailable ho jaye.

Real-Life Example:

Sochain 10,000 fake customers aik shop mein enter ho jate hain aur kuch khareedte nahi — real customers enter nahi kar sakte.

Famous Example:

2016 mein company Dyn par attack hua tha, jis ne in websites ko affect kiya:

  • Twitter
  • Netflix
  • GitHub

(Ye aik real-world referenced event hai.)

🛡️ DDoS Protection

  • Rate limiting
  • CAPTCHA
  • API Gateway
  • Load balancers
  • CDN services

  1. XSS aur DDoS mein difference?
  2. Kaunsa attack users ko target karta hai? Kaunsa servers ko target karta hai?
  3. Rate limiting kaise help karti hai?

5️⃣ Authentication vs Authorization

🔐 Authentication (AuthN)

Definition:

Verify karna ke aap kaun hain.

Example:

  • Username & password
  • OTP
  • Biometrics

🔑 Authorization (AuthZ)

Definition:

Verify karna ke aap kya access kar sakte hain.

Example:

  • Student admin panel access nahi kar sakta
  • Teacher marks upload kar sakta hai

🧠 Real-Life Example

University mein:

  • ID Card Check = Authentication
  • Lab tak access = Authorization

🔄 REST mein Common Authentication Methods

  1. Basic Authentication
  2. API Keys
  3. Token-Based Authentication
  4. JWT (JSON Web Token)
  5. OAuth 2.0

📌 JWT (JSON Web Token)

Definition:

JWT aik compact, URL-safe token format hai jo authentication ke liye use hota hai.

Structure:

Header.Payload.Signature

Example Use Case:

User logs in → Server JWT generate karta hai → Client token store karta hai → Header mein token send karta hai:

Authorization: Bearer <token>

🛡️ OAuth 2.0

Use hota hai:

  • Google
  • Facebook
  • Microsoft

Example:

"Login with Google"

6️⃣ REST mein Session Handling

❓ Session kya hota hai?

Session requests ke darmiyan user state store karta hai.

🚨 Problem:

REST stateless hai.

Har request mein saari necessary information honi chahiye.

🔄 Session Handling ke do approaches

1️⃣ Traditional Session-Based

  • Server session store karta hai
  • Client cookie mein session ID store karta hai

Problem:

  • Scalable nahi
  • Microservices ke liye hard

2️⃣ Token-Based (REST ke liye Recommended)

  • Server JWT issue karta hai
  • Client token store karta hai
  • Har request token include karti hai

Advantages:

  • Scalable
  • Stateless
  • Mobile apps ke saath kaam karta hai

🔐 Secure Session Practices

  • HTTPS use karein
  • HttpOnly & Secure cookies set karein
  • Short token expiry
  • Refresh tokens
  • Compromised tokens revoke karein

🧠 Complete Flow Example

1. User logs in
2. Server credentials validate karta hai
3. Server JWT generate karta hai
4. Client JWT store karta hai
5. Client header mein token send karta hai
6. Server token verify karta hai
7. Access granted ya denied

Key Takeaways

  • CORS browsers ko cross-origin attacks se protect karta hai
  • XSS users ko target karta hai
  • DDoS availability ko target karta hai
  • Authentication ≠ Authorization
  • REST token-based session handling prefer karta hai
  • Security multi-layered honi chahiye

📝 Important Definitions (Research mein use hon to citation require ho sakti hai)

Agar students assignments mein definitions use karein, to unhein cite karna chahiye:

  • REST – Roy Fielding ne apni doctoral dissertation (2000) mein define kiya
  • OAuth 2.0 – IETF Standard
  • JWT – RFC 7519
  • Same-Origin Policy – Browsers ke zariye defined web security model

🎓 End of Lecture Summary

REST APIs mein security optional nahi — essential hai.

Bina:

  • Proper CORS → Browser misuse
  • XSS protection → User data theft
  • DDoS protection → Service unavailability
  • AuthN & AuthZ → Unauthorized access
  • Secure sessions → Account hijacking

Aik secure API aik well-guarded university ki tarah hoti hai:

  • Gatekeeper (Authentication)
  • Access control (Authorization)
  • CCTV & Rules (Security policies)
  • Visitor log (Session handling)
